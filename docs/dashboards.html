A dashboard is a page that shows live or recent data — updated automatically or refreshed on demand. The right approach depends entirely on where your data lives and what tools you're already using. This page covers three patterns that match the stacks on this site, then digs into the cross-cutting mechanics: Sheets as a data source, Chart.js, auto-refresh, and embedding.

Approaches

Streamlit dashboard Python — fastest for data people

Streamlit gives you charts, metrics, and data tables as Python function calls. There's no HTML, no JavaScript, and no fetch — your Python code runs server-side and Streamlit renders the result. This is the fastest approach if your data is already in Python (SQLite queries, pandas DataFrames, numpy arrays).

Key widgets

WidgetUse for
st.metric(label, value, delta)KPI tile with optional up/down indicator
st.dataframe(df)Sortable, filterable table from a pandas DataFrame
st.plotly_chart(fig)Interactive Plotly chart (bar, line, scatter, etc.)
st.bar_chart(df)Quick bar chart directly from a DataFrame column
st.line_chart(df)Quick line chart directly from a DataFrame column
st.columns(n)Lay widgets side-by-side in a grid

Minimal example — metrics + bar chart

import streamlit as st
import pandas as pd
import plotly.express as px
import db  # your data layer

st.title("Engagement Dashboard")

people = pd.DataFrame(db.get_all_people())

# KPI row
c1, c2, c3 = st.columns(3)
c1.metric("Total people", len(people))
c2.metric("Active", (people["engagement"] == "Active").sum())
c3.metric("Alumni", (people["standing"] == "Alumni").sum())

# Bar chart by standing
by_standing = people["standing"].value_counts().reset_index()
by_standing.columns = ["Standing", "Count"]
fig = px.bar(by_standing, x="Standing", y="Count")
st.plotly_chart(fig, use_container_width=True)

Auto-refresh in Streamlit

import time

# re-run the entire script every 60 seconds
st.write(f"Last updated: {time.strftime('%H:%M:%S')}")
time.sleep(60)
st.rerun()
Put @st.cache_data(ttl=60) on your data-fetching functions so a rerun hits the cache instead of the database on every tick.
GAS web app + JavaScript dashboard No Python — lives inside Google's ecosystem

When your data is in Google Sheets and your frontend is a static HTML page (GitHub Pages), the pattern is: a Google Apps Script deployment serves as the backend API, and your HTML page fetches data from it. The GAS doGet function returns JSON; your JavaScript parses it and renders charts.

GAS backend — doGet returning JSON

// Code.gs (Google Apps Script)
function doGet(e) {
  const sheet = SpreadsheetApp
    .openById("YOUR_SPREADSHEET_ID")
    .getSheetByName("Data");

  const rows = sheet.getDataRange().getValues();
  const headers = rows[0];
  const data = rows.slice(1).map(row => {
    const obj = {};
    headers.forEach((h, i) => obj[h] = row[i]);
    return obj;
  });

  return ContentService
    .createTextOutput(JSON.stringify({ data }))
    .setMimeType(ContentService.MimeType.JSON);
}
After editing doGet, you must deploy a new version in GAS (Deploy → Manage deployments → Edit → New version) before the /exec URL serves the updated code. clasp push alone is not enough.

Frontend — fetch from /exec URL

// index.js or inline script in your HTML page
const GAS_URL = "https://script.google.com/macros/s/YOUR_DEPLOYMENT_ID/exec";

async function loadData() {
  const res = await fetch(GAS_URL);
  const json = await res.json();
  return json.data;  // array of row objects
}

loadData().then(data => {
  // render into a Chart.js chart or DOM table
  console.log(data);
});
CORS note: GAS /exec deployments support cross-origin requests when deployed as "Anyone" access. If you get CORS errors, check: (1) deployment access is set to "Anyone, even anonymous", (2) you're fetching the /exec URL not the /dev URL.
Google Sheets published CSV Simplest read-only data source, no GAS needed

If your Sheet is public and you only need to read it, you can skip the GAS backend entirely. Google Sheets can publish any sheet as a CSV that any client can fetch directly with no authentication.

How to get the CSV URL

In your Google Sheet: File → Share → Publish to web → select the sheet tab → choose Comma-separated values (.csv) → Publish. Copy the URL. It looks like:

https://docs.google.com/spreadsheets/d/SPREADSHEET_ID/export?format=csv&gid=SHEET_GID

Fetch and parse in JavaScript

const CSV_URL = "https://docs.google.com/spreadsheets/d/.../export?format=csv&gid=0";

async function loadCSV() {
  const res = await fetch(CSV_URL);
  const text = await res.text();

  // simple manual parse (first row = headers)
  const lines = text.trim().split("\n");
  const headers = lines[0].split(",");
  const data = lines.slice(1).map(line => {
    const vals = line.split(",");
    const obj = {};
    headers.forEach((h, i) => obj[h.trim()] = vals[i]?.trim());
    return obj;
  });
  return data;
}
For Sheets with commas inside cells (quoted fields), the manual split above will break. Use Papa Parse instead — include it via CDN and call Papa.parse(text, { header: true }).
This only works for public Sheets. If your Sheet is private, use the GAS /exec approach or gspread with a service account instead.

Chart.js basics

Chart.js is the standard library for browser-based charts in the stacks on this site. Include it via CDN — no npm, no build step.

<!-- Add to your HTML <head> -->
<script src="https://cdn.jsdelivr.net/npm/chart.js"></script>

<!-- Canvas element where the chart renders -->
<canvas id="myChart" width="600" height="300"></canvas>

Minimal bar chart

const ctx = document.getElementById("myChart").getContext("2d");

new Chart(ctx, {
  type: "bar",
  data: {
    labels: ["Jan", "Feb", "Mar", "Apr"],
    datasets: [{
      label: "Responses",
      data: [12, 19, 8, 24],
      backgroundColor: "#0f3460",
    }]
  },
  options: {
    responsive: true,
    plugins: { legend: { display: false } }
  }
});

Building labels and data from fetched rows

// after loadData() returns an array of objects like { month: "Jan", count: "12" }
loadData().then(rows => {
  const labels = rows.map(r => r.month);
  const values = rows.map(r => parseInt(r.count));

  new Chart(ctx, {
    type: "bar",
    data: {
      labels,
      datasets: [{ label: "Count", data: values, backgroundColor: "#0f3460" }]
    }
  });
});

Auto-refreshing data

Auto-refresh makes sense when data changes frequently and users want to see it without reloading. For slowly-changing data (updated once a day), it just adds network load for no benefit.

JavaScript — setInterval

let chart = null;  // keep a reference to update it

async function refresh() {
  const data = await loadData();
  if (chart) {
    // update existing chart in-place (no flicker)
    chart.data.labels = data.map(r => r.label);
    chart.data.datasets[0].data = data.map(r => r.value);
    chart.update();
  } else {
    chart = new Chart(ctx, { /* initial config */ });
  }
}

refresh();                        // run immediately on load
setInterval(refresh, 30000);    // then every 30 seconds
Calling chart.update() on the existing Chart instance (instead of destroying and recreating it) gives a smooth animated update rather than a flash of blank canvas.

Streamlit — time-based rerun

import time
import streamlit as st

# show data, then wait and reload the whole page
placeholder = st.empty()
with placeholder.container():
    st.dataframe(load_data())
    st.caption(f"Refreshed at {time.strftime('%H:%M:%S')}")

time.sleep(30)
st.rerun()
When not to auto-refresh: if your data source is Google Sheets via gspread, every refresh hits the Sheets API. Google's quota is 300 read requests per minute per project — a dashboard with 10 simultaneous users refreshing every 30s will hit this. Use @st.cache_data(ttl=60) to serve cached data between refreshes.

Embedding a dashboard in another page

If your dashboard is a standalone HTML page (GitHub Pages or a GAS web app), you can embed it in another page using an <iframe>:

<iframe
  src="https://your-dashboard-url.github.io/dashboard.html"
  width="100%"
  height="500"
  frameborder="0"
  style="border-radius: 8px;"
></iframe>
GAS web apps can only be embedded in iframes if the deployment's "Who has access" is set to "Anyone" (not "Anyone with Google account") and the embedding page is not blocked by the GAS app's X-Frame-Options header. In practice, embedding GAS apps in iframes can be unreliable — a standalone page with its own fetch() call is more predictable.
