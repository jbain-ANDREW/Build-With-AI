What this stack does

This stack lets you write LaTeX in VS Code with real-time PDF preview and Claude as an AI co-author, while keeping an Overleaf project in sync so collaborators can view and edit in the browser.

VS Code

Claude Code
AI on .tex files

You write and edit locally in VS Code. Claude Code edits .tex files directly — fixing errors, rewriting sections, generating tables. A git push syncs everything to Overleaf, where collaborators can edit in the browser. A git pull brings their changes back.

Setup

1
Install LaTeX Workshop in VS Code

Open VS Code, go to the Extensions panel (Ctrl+Shift+X), and search for LaTeX Workshop by James Yu. Install it.

LaTeX Workshop automatically detects your LaTeX distribution and compiles on save. The default build recipe is pdflatex → bibtex → pdflatex × 2, which handles most documents including those with bibliographies.

Verify the install

Create a test file hello.tex and save it. VS Code should compile automatically and open a PDF preview panel.

% hello.tex — paste this to test
\documentclass{article}
\begin{document}
Hello, world.
\end{document}

Press Ctrl+Alt+B to build manually, or Ctrl+Alt+V to open the PDF viewer.

Useful settings (settings.json)

Add these to your VS Code settings.json for a smoother experience:

{
  "latex-workshop.view.pdf.viewer": "tab",
  "latex-workshop.latex.autoBuild.run": "onSave",
  "latex-workshop.latex.clean.fileTypes": [
    "*.aux", "*.bbl", "*.blg", "*.log", "*.out", "*.toc"
  ],
  "latex-workshop.latex.autoClean.run": "onSucceeded"
}

autoClean removes build artefacts after a successful compile so your folder stays tidy — important when the project is also a Git repo.

2
Use Claude Code on your .tex files

Claude Code runs in the terminal alongside VS Code and edits .tex files directly — the same way it edits any code file. Open a terminal in your project folder and run claude.

Things Claude is especially good at in LaTeX

  • Fixing compilation errors — paste the error log and ask Claude to diagnose and fix it
  • Rewriting sections — "rewrite the introduction to be more concise"
  • Generating tables — describe a table in plain English; Claude writes the tabular environment
  • Equations — describe the math; Claude writes the equation or align block
  • Bibliography cleanup — reformatting .bib entries, fixing missing fields
  • Boilerplate — figure environments, subfigures, custom commands, preamble packages

Add a CLAUDE.md to your project

A CLAUDE.md in your project root gives Claude persistent context about the document so you don't repeat yourself every session:

# CLAUDE.md — project instructions for Claude Code

This is a journal paper submitted to IEEE Transactions on X.
Main file: main.tex
Bibliography: refs.bib
Style: IEEE two-column, \documentclass[journal]{IEEEtran}

Do not alter section headings.
Citation style: numeric [1], not author-year.
Avoid passive voice in abstract and introduction.
Tip: use Claude to fix LaTeX errors. When LaTeX Workshop shows a build error, open the log panel, copy the relevant lines, and ask Claude: "LaTeX gave this error — fix it." Claude will find and correct the offending line.
3
Connect to Overleaf via the Git bridge Primary

Overleaf's Git bridge gives every project a private Git remote. You push from VS Code and your collaborators see the changes live in Overleaf.

One-time setup

  1. In Overleaf, open your project and go to Menu → Git.
  2. Copy the clone URL — it looks like:
    https://git.overleaf.com/YOUR_PROJECT_ID
  3. In your terminal, clone it into a local folder:
    git clone https://git.overleaf.com/YOUR_PROJECT_ID my-paper
  4. When prompted for credentials, use your Overleaf email and password.
    If you use SSO (Google login), you'll need to set a password first under Account → Password.
Existing local files? If you already have .tex files locally, clone the Overleaf repo first, then copy your files into the cloned folder, then commit and push.

Storing credentials (optional but recommended)

So Git doesn't ask for your password every push:

# Windows: use Git Credential Manager (installed with Git for Windows)
git config --global credential.helper manager

# Mac
git config --global credential.helper osxkeychain

Daily workflow

# Pull any changes collaborators made in Overleaf
git pull

# Edit files in VS Code (with Claude if needed), then:
git add .
git commit -m "Revised introduction"
git push    # syncs to Overleaf immediately
One branch only. The Overleaf Git bridge exposes a single master branch. You cannot use feature branches — anything pushed to master goes live in Overleaf. Keep your commits clean.
4
Alternative: GitHub sync Alternative

On Overleaf's Premium tier, you can link a project directly to a GitHub repository instead of using the Git bridge. Overleaf pushes and pulls from GitHub, and you work from the GitHub remote as normal.

Setup

  1. Create a GitHub repository for your paper (can be private).
  2. In Overleaf, go to Menu → GitHub.
  3. Connect your GitHub account if prompted, then link to the repository.
  4. Clone the GitHub repo locally as you normally would:
    git clone https://github.com/YOUR_ORG/YOUR_PAPER.git

Workflow difference

Overleaf does not auto-sync — you push to GitHub from VS Code, then Overleaf merges in when you or a collaborator clicks Menu → GitHub → Pull inside Overleaf. It's a manual merge step on the Overleaf side.

Git bridge
  • Overleaf-hosted remote
  • Push = instant Overleaf update
  • One branch (master)
  • Requires paid plan
GitHub sync
  • GitHub-hosted remote
  • Overleaf pulls manually
  • Full Git branching
  • Requires Premium tier

Use Git bridge when collaborators live primarily in Overleaf and you want changes to appear instantly. Use GitHub sync when you want full branching, CI, or an audit trail on GitHub.

Common issues

Merge conflicts with Overleaf collaborators

If a collaborator edits in Overleaf while you edit locally, a git pull may produce a conflict. Overleaf inserts conflict markers the same way GitHub does. Resolve them in VS Code's merge editor, then git add and git push.

Authentication errors on push

If you signed up for Overleaf via Google (no password set), the Git bridge will reject your credentials. Go to Overleaf → Account settings → Password and set one.

LaTeX Workshop not finding pdflatex

On Windows with MiKTeX, make sure MiKTeX's bin folder is on your system PATH. Restart VS Code after installing MiKTeX. You can verify with pdflatex --version in a terminal.

Build artefacts cluttering Git

Add a .gitignore to keep compiled output out of your commits:

# .gitignore for LaTeX
*.aux
*.bbl
*.blg
*.log
*.out
*.toc
*.synctex.gz
*.fls
*.fdb_latexmk
*.pdf
Whether to commit the PDF is a project choice. Committing it means Overleaf always has a compiled copy, but it inflates repo size. For papers, most teams omit it.

SyncTeX: jump from PDF to source

LaTeX Workshop supports SyncTeX — click a location in the PDF preview and the cursor jumps to the corresponding line in the .tex file. Use Ctrl+click in the PDF panel, or Ctrl+Alt+J from the editor to jump to the PDF.

Claude prompts that work well

These prompts work reliably in Claude Code when working on a LaTeX project:

Fix a compilation error

"LaTeX build failed with this error:
! Undefined control sequence.
l.47   \tightlist
Fix it."

Generate a table from data

"Write a LaTeX table with three columns: Method, Accuracy (%), Runtime (s).
Rows: Baseline 72.3 1.2, Ours 89.1 1.4, Oracle 94.0 0.9.
Use booktabs style (toprule, midrule, bottomrule)."

Rewrite a passage

"Rewrite the abstract in section.tex to be under 150 words.
Keep all technical claims. Use active voice."

Add a figure environment

"Add a figure environment after line 83 in results.tex.
File: figures/accuracy_curve.pdf
Caption: Training accuracy over epochs for all three models.
Label: fig:accuracy"
