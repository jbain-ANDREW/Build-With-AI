"AI" is not one thing — it's a stack of distinct layers, each solving a different problem. Knowing which layer you're actually working with (or need) saves you from over-building (writing agent code when a better prompt would do) or under-building (expecting a plain prompt to know things it can't possibly know). The five cards below go from the most basic layer to the most capable, in order. Click any to expand it.

Foundation Models The base layer — the "brain" itself

A foundation model is a large model trained once on a broad swath of data (text, code, sometimes images/audio) and then reused as the base for many different tasks, instead of training a new model from scratch for each one.

Examples

  • Claude (Anthropic)
  • GPT (OpenAI)
  • Gemini (Google)
  • Llama (Meta) — open-weight
  • Mistral — open-weight

Properties that matter when choosing one

  • Context window — how much text it can consider at once
  • Modality — text-only vs. vision/audio/code-aware
  • Open-weight vs. API-only — can you run it yourself?
  • Cost — price per token in, per token out

Everything else on this page — prompts, RAG, agents, MCP — is built on top of a foundation model. None of them work without one underneath.

Use this layer when: you're deciding which AI "brain" powers your app or feature. See the Model Comparison page for current options and pricing.
Prompts The only interface you have

A prompt is the text you send the model. It is the entire interface — there is no other dial, button, or setting that changes what the model does on a given request besides what you put in the prompt (and a few API parameters like temperature).

Common techniques

  • System prompt — standing instructions for the whole conversation
  • Zero-shot — just ask, no examples
  • Few-shot — show 1-3 examples of the output you want
  • Chain-of-thought — ask it to reason step by step before answering
  • Structured output — ask for JSON matching a schema

Common misconception

  • A better prompt cannot teach the model a fact it was never trained on
  • Prompting elicits capability already in the model — it doesn't add new capability
  • If the model needs outside facts, that's RAG (next card), not a cleverer prompt
Use this layer when: starting any AI feature. It's free, instant, and fully reversible — always try a better prompt before reaching for RAG or an agent.
RAG Retrieval-Augmented Generation — giving it facts it doesn't know

A foundation model only knows what was in its training data, frozen at a cutoff date. RAG fixes that by fetching relevant outside information at the moment of the request and inserting it into the prompt — so the model answers using facts it was never trained on.

The pipeline, in plain language

  • Break your documents into chunks
  • Convert each chunk into a vector (an "embedding") and store it
  • When a question comes in, convert it to a vector too
  • Retrieve the most similar stored chunks
  • Paste those chunks into the prompt, then ask the model to answer

Good fits

  • Answering questions about your own documents or codebase
  • Anything that changed after the model's training cutoff
  • Private data the model could never have been trained on
Use this layer when: the answer depends on information the model can't possibly already know — your files, your data, today's news.
Agents From one answer to a loop of actions

A plain prompt is one request, one response. An agent changes the shape entirely: the model plans a step, takes an action (run code, call a tool, search the web, edit a file), looks at what happened, and decides the next step — repeating until the goal is done or it gives up.

The shift

  • Single-shot: "What's the capital of France?" → one answer
  • Agentic: "Fix the failing test" → reads files, runs the test, edits code, reruns, repeats
  • Agents typically combine prompting, tool use, and often RAG, in a loop

A concrete example

  • Claude Code (what's running this conversation) is an agent: it reads your files, runs shell commands, edits code, and iterates based on what it observes
  • A support bot that looks up an order, decides a refund is warranted, and issues it is also an agent
Use this layer when: the task needs multiple steps, real-world actions, or decisions made along the way — not just a single answer.
MCP Model Context Protocol — the standard wiring for tools

Once you have an agent, it needs to call tools — a database, a file system, a Slack workspace, a calendar. Without a standard, every tool needs custom integration code for every model. MCP (created by Anthropic, now widely adopted) is an open protocol so any MCP-compatible agent can talk to any MCP-compatible tool without bespoke glue code in between — "USB-C for AI," one connector instead of a different cable for every device.

What MCP standardizes

  • How an agent discovers what tools/data a server offers
  • How it calls a tool and gets results back
  • How it reads from a data source the server exposes

Why it matters

  • Build one MCP server for your tool, and every MCP-compatible agent can use it
  • No more "N tools × M models" worth of custom integration code
  • This is the plumbing layer underneath the tool calls an agent makes
Use this layer when: you're building or connecting a tool, database, or data source that an agent should be able to call.
