A tech stack is the combination of tools and services that together make a project work. Picking the right stack early saves a lot of rework. The stacks below cover the full range from zero-infrastructure static sites to real-time multi-user apps — each with distinct trade-offs on speed-to-build, flexibility, and deployment complexity. Click any stack to expand it.

GitHub Pages — Static HTML/CSS/JS Simplest possible hosting

Strengths

  • Zero infrastructure — push to GitHub, it's live
  • No build step, no dependencies, no package.json
  • Free hosting, permanent URLs, works everywhere
  • Easy for beginners to inspect and learn from
  • Perfect for content-first sites: tutorials, docs, portfolios

Weaknesses

  • No dynamic data — everything hardcoded or fetched from external APIs
  • No authentication without a third-party service
  • No shared state between pages
  • Updating repeated elements (nav, footer) requires editing every file
Use when: teaching content, documentation, project landing pages, or anything mostly static and updated infrequently. The simplest possible hosting story.
Python + Streamlit Fastest to build data tools

Two backend variants: Google Sheets (cloud, stakeholder-editable) or SQLite (local, relational, schema-enforced). Same frontend and deployment model for both.

Strengths

  • Entire API layer and frontend collapse into Python — no HTML, CSS, or JS
  • Full pandas / Plotly / numpy ecosystem for data work
  • Google Sheets variant: stakeholders edit data without opening the app
  • SQLite variant: real relational DB with foreign keys and versioned migrations
  • Streamlit Cloud: git push → live with no server config
  • Session state is built in — no state management decisions

Weaknesses

  • UI constrained by Streamlit's widget model — less flexible than React
  • Not suitable for public-facing or high-traffic sites (session-per-user)
  • No real-time sync — data refreshes on demand, not live
  • Local SQLite variant: single-user only, no public URL without extra work
Use when: academic or institutional tools where data lives in Sheets or SQLite; any workflow needing pandas, rich visualization, or fast CRUD UI with minimal front-end code.
Python + Flask + SQLite Full control, local-only

Strengths

  • Full control over every HTTP route and Jinja2 template
  • SQLite: real relational DB, zero setup, no cloud dependency
  • Lightweight — easy to add routes, logic, and templates
  • Runs entirely locally; data never leaves your machine
  • Good for complex business logic that doesn't fit Streamlit's widget model

Weaknesses

  • Local-only by default — sharing requires tunneling or hosting work
  • More boilerplate than Streamlit for simple CRUD views
  • No built-in auth or multi-user support
  • No live updates — requires manual capture-and-refresh cycle
  • SQLite doesn't scale to concurrent multi-user access
Use when: personal productivity tools needing real data logic and persistence, Gmail/Calendar API access, and local-only privacy. Not for sharing with others without significant extra work.
React + Vite + Firebase + Vercel Real-time, multi-user, production-grade

Strengths

  • Real-time sync via Firestore onSnapshot — all users see changes instantly
  • Firebase Auth handles login with zero backend code
  • Component model makes complex UIs manageable (tabs, modals, expandable rows)
  • Vercel deployment: fast, free, automatic on git push
  • Scales to many concurrent users without server management

Weaknesses

  • High setup complexity: Node, npm, Firebase project, Firestore rules, Vercel account
  • Mandatory build step (Vite / webpack) before any deployment
  • Cold-start learning curve for React state and component patterns
  • Overkill for simple or single-user tools
  • Data in Firestore (NoSQL) — not directly spreadsheet-editable
Use when: multi-user collaboration where real-time sync matters and the UI needs to be polished and interactive. Not for solo tools, analytical work, or anything where data needs to live in Sheets.
Google Apps Script + Sheets + GitHub Pages Zero infrastructure, Google-native

Strengths

  • Zero infrastructure — deploys as a URL directly from Google's servers
  • Native access to Sheets, Drive, Gmail, Calendar — no OAuth keys needed
  • Config live-editable in Sheets by non-developers
  • Works on any device; phone camera via capture="environment"
  • Free within GAS quotas (generous at personal and small-team scale)
  • clasp enables local editing with git version control synced to GAS

Weaknesses

  • Two separate deployment steps and two separate URLs (GitHub Pages + GAS /exec)
  • No real-time updates — data loads on demand
  • UI flexibility limited vs. React; no npm ecosystem
  • GAS runtime is Google-controlled — quota limits cap scale
  • Multi-Google-account Chrome environments can cause access issues
Use when: personal or small-team tools where data is already in Sheets, phone-first data capture, no hosting budget, or config needs to be editable by non-developers directly in Sheets.
